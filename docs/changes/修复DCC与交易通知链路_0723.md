# 修复 DCC 与交易通知链路

## 变更信息

- 变更时间：2026-07-23 20:44:42 +08:00
- 变更类型：运行阻断修复、交易通知修复、端到端验证
- 适用环境：本机 Docker Desktop、JDK 8、Spring Boot `dev` 环境

## 变更内容

### DCC 注解修复

- 将 `DCCService` 使用的自定义 `com.hjs.study.types.annotation.DCCValue` 改为当前已启用的 xfg-wrench starter 注解。
- 修复 `downgradeSwitch`、`cutRange`、`scBlacklist`、`cacheSwitch` 未被初始化的问题。
- 应用启动后会在 Redis 中初始化对应的 `group-buy-market_*` 配置键。

### 成团通知修复

- `TradeSettlementOrderService` 接收仓储层返回的 `NotifyTaskEntity`。
- 成团产生通知任务后，通过现有业务线程池异步调用 `ITradeTaskService.execNotifyJob`。
- MQ 投递失败时保留本地通知任务，由原有零点补偿任务继续重试。
- 避免成团通知只能等待每天零点任务才发送的问题。

### 退款通知状态修复

- 为 `TradeRepository.paidTeam2Refund` 返回的 `NotifyTaskEntity` 补充 `uuid`。
- 修复已支付且已成团退款消息发送成功后，通知任务状态更新 SQL 无法命中的问题。
- 防止已经投递并确认的退款消息被补偿任务重复发送。
