# 拼团全流程前端

## 变更信息

- 变更时间：2026-07-23 22:27:13 +08:00
- 变更类型：本地联调前端、RabbitMQ 管理接口配置
- 页面目录：`docs/ui/group-buy-flow/`
- 适用环境：本机 Docker Desktop、Spring Boot `dev` 环境

## 变更内容

### 全流程实验台

- 新增独立的拼团全流程单页，不覆盖仓库原有商品演示页面。
- 复用 `docs/ui/html/images/sku-13811216-01.png` 商品图片，展示真实商品试算价格和活动统计。
- 支持修改应用地址、RabbitMQ 管理地址、商品、来源和渠道配置。
- 默认生成三位不重复的测试用户及 12 位外部交易号，并通过 `sessionStorage` 保存本轮状态。
- 支持发起新团或从试算结果中选择已有团队。
- 支持逐笔锁单、支付结算、释放未支付锁单和退款已支付订单。
- 提供“自动执行至成团”，按参与者顺序完成三次锁单和三次结算。
- 展示团队 ID、锁单进度、结算进度、订单 ID、支付价格和参与者业务状态。
- 记录每次业务接口的请求、响应、耗时和结果，便于定位联调失败。

### RabbitMQ 观察

- 页面通过 RabbitMQ Management API 读取成团、退款两个队列的累计发布数、确认数、积压数和消费者数量。
- 在 RabbitMQ 配置中允许本机静态页面执行 Management API 跨域请求。
- Compose 为 RabbitMQ 挂载 `docs/dev-ops/rabbitmq/rabbitmq.conf`，继续复用原命名卷，不删除 RabbitMQ 数据。
- RabbitMQ 对外端口仍只绑定 `127.0.0.1`，管理接口没有暴露到局域网。

### 响应式与交互

- 桌面端使用交易编排与队列观察双栏布局，移动端切换为单栏。
- 移动端参与者区域改为两列紧凑布局，不需要横向滚动即可操作退款和后续步骤。
- 连续自动操作最多同时展示三条结果提示，避免遮挡主要操作区域。
- 支持重置本轮测试，重置时保留环境连接配置并生成新的用户和交易号。

## 运行方式

在仓库根目录执行：

```powershell
py -m http.server 4173 --bind 127.0.0.1 --directory docs/ui
```

浏览器访问：

```text
http://127.0.0.1:4173/group-buy-flow/
```

当前任务已在后台启动该静态服务。应用默认地址为 `http://127.0.0.1:8091`，RabbitMQ 管理地址为 `http://127.0.0.1:15672`。
